POR QUE A TAXA NÃO APARECE?

As medições pertencem ao trecho que transmite o áudio.

O Mobile precisa medir bytes recebidos durante a reprodução, e o Desktop precisa informar erros de envio. O painel não transforma “online” em qualidade de stream. Assim que os clientes reportarem medidas, elas podem ser exibidas aqui com unidade e horário.

CÓPIA DE SEGURANÇA

Guarde suas contas e dispositivos

O arquivo criptografado inclui contas, dispositivos, sessões e a chave desta instância. Ele só pode ser aberto com a senha escolhida. Guarde o arquivo e a senha em local seguro.

Antes de restaurar, o Cobre cria uma cópia criptografada dos dados atuais junto do arquivo escolhido e reinicia o serviço.

VERSÃO 0.5.0-beta.10

Ícone próprio do Cobre Server

BETA
  • O app e o painel agora usam o símbolo Cobre Server com módulos centrais no lugar das barras de áudio.
  • A moldura em cobre preserva a identidade do ecossistema e diferencia o Server do Desktop.

VERSÃO 0.5.0-beta.9

Permissões renováveis para reprodução contínua

BETA
  • A aprovação do acesso ao Desktop vale por 30 dias.
  • O aparelho usa tokens assinados de 10 minutos e pode renová-los enquanto a permissão estiver ativa.
  • Revogar o acesso ou remover o aparelho interrompe as renovações. Desktop e Mobile ainda precisam integrar este fluxo.

VERSÃO 0.5.0-beta.9

Painel de acessos ao Desktop

BETA
  • Consulte permissões ativas por conta, aparelho, Desktop, escopos e validade.
  • Revogue permissões pela central local do Cobre Server, protegida contra pedidos vindos de outras origens.
  • A integração de Desktop e Mobile com as permissões ainda está pendente; esta tela permite gerir as concessões emitidas.

VERSÃO 0.5.0-beta.9

Autorização de acesso por Desktop

BETA
  • Mobile e TV podem solicitar acesso a um Desktop específico; o host lista e aprova ou recusa cada pedido autenticado.
  • Concessões assinadas expiram, carregam permissões limitadas e podem ser validadas e revogadas.
  • A integração com Desktop e Mobile ainda está pendente; esta atualização prepara a API do Server, sem habilitar ainda a biblioteca ou a transmissão.

VERSÃO 0.5.0-beta.6

Atualizador resiliente ao limite do GitHub

BETA
  • Se a API do GitHub limitar as consultas, o app busca as notas no feed oficial de releases.
  • O instalador Windows x64 continua validado por tamanho, origem oficial e SHA-256 antes de ser liberado.
  • Inclui teste de fallback desde a consulta até a verificação do pacote.

VERSÃO 0.5.0-beta.5

HTTPS configurável

BETA
  • Importa certificado e chave PEM e confere validade e correspondência antes de ativar.
  • Com HTTPS ativo, a API não mantém HTTP paralelo; o endereço dos aplicativos deve ser atualizado para HTTPS.
  • Certificado autoassinado não é confiável automaticamente. Ainda falta testar login HTTPS nos aparelhos reais.

VERSÃO 0.5.0-beta.4

Atualização no próprio aplicativo

BETA
  • Verifica versões oficiais, mostra notas e baixa o instalador Windows x64.
  • Confere o SHA-256 antes de liberar e antes de abrir o instalador.
  • Atualizar por cima mantém os dados da instância no perfil do Windows.

VERSÃO 0.5.0-beta.3

Pareamento Cobre TV mais seguro

BETA
  • Aprovação e resgate de códigos agora são atômicos: chamadas simultâneas não criam TVs duplicadas nem liberam duas sessões.
  • JSON enviado à API precisa ser objeto; valores nulos, listas e escalares são recusados.
  • 24/24 testes passaram. A API continua usando HTTP na rede local e o app de TV ainda é um protótipo.

VERSÃO 0.5.0-beta.2

Cópia de segurança criptografada

BETA
  • Configurações exportam e restauram contas, dispositivos, sessões e chave da instância em arquivo protegido por senha.
  • O backup é validado antes da confirmação; uma cópia criptografada do estado atual é salva ao lado do arquivo de origem antes da substituição.
  • A restauração reinicia o serviço para reabrir a base restaurada.

Ainda falta validar o fluxo completo pela interface no Windows com dados reais. A API continua usando HTTP sem criptografia na rede local.

VERSÃO 0.4.0-beta.4

Medição real do áudio recebido

BETA
  • O diagnóstico apresenta taxa recebida e latência inicial reportadas pelo Mobile durante reprodução de uma faixa do Desktop.
  • As medidas do stream ficam separadas da latência do catálogo e da presença Cobre ID.
  • O Cobre Server continua sem retransmitir áudio; o stream segue diretamente pela rede local.

Os dados aparecem após o Mobile tocar uma faixa do Desktop e enviar o próximo heartbeat. Com contribuição de @dilucas00.
